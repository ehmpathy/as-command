# case=2 — unawaited logs land in order

## narrative

a command author writes logic that fires `context.log.info(...)` in a loop with no await — the common shape, since `LogMethods` reads as fire-and-forget — then returns. the command completes. the author opens `log.json`: every entry is there, in the order the calls were made, followed by `output.result`, `output.files`, and the final `]`. no entry trails the `]`, and none is interleaved.

## bdd

```
[t0] given a command whose logic fires N log.info calls without await
[t1] when  the command completes
[t2] then  log.json holds all N entries, in call order
[t3] and   log.json ends with the final `]`, after the last entry
```

## the test must bite

a probe of 200 unserialized concurrent appends (larger payloads first) landed out of order in 4 of 5 runs, clean in 1. so the order test repeats its burst across several runs; one clean run must not let unserialized code pass.

## why sharp, and its fail-safe

the edge is a **limit**: a burst of N overlapped writes, where unserialized appends reorder (the probe above). the actor sees success only because the limit holds. per `define.experience`, a limit's fail-safe is that the last valid input still succeeds, whole and in place:

- holds: all N entries land, none dropped, none reordered — one promise chain carries `[`, each entry, and `]`, so no write can overtake another
- no error to teach: the burst is valid use, so there is no rejection; the proof is the order test that repeats its burst
