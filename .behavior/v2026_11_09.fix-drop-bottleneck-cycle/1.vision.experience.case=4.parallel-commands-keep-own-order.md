# case=4 — parallel commands each keep their own order

## narrative

a caller runs two commands at once via `Promise.all`. both log without await. each writes its own `log.json` under its own run dir. the one chain is global, so writes from both interleave across files — but within each file, entries land in that command's call order, between its own `[` and `]`.

## bdd

```
[t0] given two commands invoked at once, each fires N unawaited log.info calls
[t1] when  both complete
[t2] then  each log.json holds its own N entries, in its own call order
[t3] and   each ends with its own `]`
```

## test owed

an alterpath by care, but the wish's proof ("in order under concurrent calls") reads as concurrent invocations too — so this case is tested, not only demoed.

## cost

a global chain serializes appends across commands. appends are small; the prior limiter meant a global cap of 1. a per-file chain is a clean rework if throughput ever matters.
