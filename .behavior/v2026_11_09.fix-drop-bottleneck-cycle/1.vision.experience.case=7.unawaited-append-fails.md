# case=7 — an unawaited append fails

## cell

unawaited × one call × append fails × logic returns (inventory cell 19). the throw variant is cell 20.

## narrative

an unattended caller (a nightly ci job) runs a command whose logic logs without await. mid-run, the run dir is removed and one append rejects with `ENOENT … log.json`. nobody awaits that promise, so node raises an unhandled rejection: the error, with its code and path, prints to stderr and the process exits non-zero. the ci job goes red and its log shows the path. the chain does not wedge: later appends and the final `]` are still attempted.

## bdd

```
[t0] given logic that fires log calls without await, and an append that will reject
[t1] when  the append rejects
[t2] then  the rejection surfaces at the process level with the fs code and path (loud)
[t3] and   later scheduled writes still run (the chain stays live, as in case=3)
```

## fail-safe

- loud: an unhandled rejection is never silent — node ≥15 exits non-zero by default; older node prints the error to stderr
- teaches the fix: the fs error names its code and path
- no new hazard: under bottleneck the same unawaited `schedule` promise rejected the same way; the change neither adds nor hides it
- not swallowed on purpose: a catch-and-ignore here would hide a lost log entry (`rule.forbid.failhide`)
