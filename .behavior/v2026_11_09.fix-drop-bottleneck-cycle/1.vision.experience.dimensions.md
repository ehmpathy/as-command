# 1.vision.experience.dimensions

## .subject — the root split

| subject | actor values | what varies |
|---|---|---|
| **lint** | adopter repo | whether its import graph still reaches bottleneck |
| **file-log** | command author · unattended caller (cron / ci) | the four axes below |

the log axes do not apply to the lint subject: an adopter at lint runs no command, so it makes no log call, holds no write in flight, and has no append or logic outcome. those cells are **impossible** (nature), recorded once here rather than as 24 empty rows (the same 2 × 3 × 2 × 2 product as file-log, for the one lint actor).

## .axes under file-log

| axis | positions | orthogonal because |
|---|---|---|
| log call | awaited · unawaited | how the logic calls `context.log.*` is the author's choice, set in source; it fixes no value of the other axes |
| in flight | one call · many calls in one command · many commands at once | counts the calls the source **schedules** — set by the caller's loop and its `Promise.all`, not by await style. how many of them **overlap at runtime** is the product of this axis and `log call`: awaited calls in one command run one at a time (cell 3), unawaited ones overlap (cell 15), and across commands both overlap (cells 5, 17) |
| append outcome | succeeds · fails | set by the disk and the run dir (space, a dir removed), outside the code's control |
| logic outcome | returns · throws | set by the author's logic and its input, independent of how it logs |

### call time — a fifth axis, walked apart

| axis | positions | orthogonal because |
|---|---|---|
| call time | while the logic runs · after the logic settles | set by whether the author's source detaches a log call (a timer, an unawaited async fn) past its return; it fixes no value of the four axes above |

the 24 cells above hold `call time = while the logic runs`. under `after the logic settles`, the `log call`, `in flight`, and `logic outcome` axes collapse: the run is over, so the entry lands after `]` whatever their value. only `append outcome` still varies → 2 cells (25, 26), walked in `case=_`.

### metadata — a sixth axis, walked apart

| axis | positions | orthogonal because |
|---|---|---|
| metadata | json-safe · unserializable (circular ref, bigint) · mutated after the call | set by what the author passes to `context.log.*`, and whether the author's source changes that object later; it fixes no value of the other axes |

the 24 cells hold `metadata = json-safe`. under `unserializable`, only `logic outcome` changes what a reader sees (an error with a circular ref is the common case), so 2 cells (27, 28). the same axis reaches two more doors, the command's input (hashed into the run id) and its output (rendered into `out.json`): cells 29, 30. under `mutated after the call`, only the moment of capture matters (the file must hold the object as it was at the call, not at the write), so 1 cell (31). all walked in `case=_`.

### thrown value — a seventh axis, under `logic outcome = throws`

| axis | positions | orthogonal because |
|---|---|---|
| thrown value | an `Error` · a value that is not an `Error` (string, plain object) | set by the author's logic or a library it calls; js lets any value be thrown, and it fixes no value of the log axes |

it varies only what `output.error` holds and what the caller receives, so 2 cells (32, 33).

### output content — an eighth axis, under `logic outcome = returns`

| axis | positions | orthogonal because |
|---|---|---|
| output content | a string · a json object · `undefined` · unserializable | set by the author's return type; it fixes no value of the log axes |

each position renders `out.json` its own way: cells 34, 35, 36, and 30 (unserializable, above).

### internal contracts, held at their own grain

three behaviors are not reached by an actor choice, yet each is a contract another module leans on, so each is held as a cell rather than left orphaned behind its test: a repeated `open` or `seal` of a run log converges (37), an entry with no metadata omits the key (38), and scheduled tasks run one at a time in call order (39).

### output artifacts and console — a third subject

the author's outputs beyond `log.json` and `out.json`: an artifact written via `context.out.write` (40), and the console line the adopter's logger emits (41). each is a single path with no axis of its own, so each is one cell.

actor within file-log: the unattended caller walks the same 24 cells as the author. it differs only in who reads a failure — a human, or a ci run that reads the exit code — so it adds no cell, and is named on the failure cases (case=3, case=7).

## .boundaries the cells cross

logic→chain seam · order limit (all N, in order) · thrown rejection · `finally`→`]` seam · failed-append rejection (awaited) · failed-append rejection (unawaited → process level)
