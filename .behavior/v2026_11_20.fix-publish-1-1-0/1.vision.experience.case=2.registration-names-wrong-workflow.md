# case=2 — the registration names the wrong workflow

sharp × critipath. the likeliest admin slip: the publish command lives in `.publish-npm.yml`, so that file looks like the one to register.

## narrative

the admin registers `.publish-npm.yml`. the releaser reruns, and `verify oidc auth` gets http 404 and exits 1 before build. no version is published, so no partial or wrong release exists. it fails **fast** (before build) and **loud** (a red run with an `::error::` line and the access url).

the error does not teach the fix by itself: it names where, not what to enter. the fix arrives in one hop. the releaser opens the ask in `1.vision.yield.md`, whose step 1 names `workflow filename: publish.yml (the caller, not the reusable .publish-npm.yml)` and warns of this exact slip. the admin edits that one field and the releaser reruns. that hop is the taught step, and it costs one read.

## timeline

```
[t5] when the releaser reruns
[t6] then case=1 [t3..t5] follows
```
