# case=5 — a second run after 1.1.0 is on npm

happy × alterpath. it walks the yield's claim that a repeat is safe: a second `gh run rerun`, or a tag re-push, after the first publish lands.

## narrative

the releaser reruns the job a second time, unsure the first one landed. `verify oidc auth` passes and the build runs. `npm publish` fails, since npm forbids a republish of `1.1.0`. the `idempotify` step then runs (`if: steps.publish.outcome == 'failure'`, `.publish-npm.yml`). it finds `1.1.0` on npm and compares the shasum of a local pack (computed, never uploaded) with the registry's `dist.shasum`.
- they match → it prints `publish: idempotent success` and the run goes green
- they differ (a build that is not byte-for-byte reproducible) → it exits 1 with both shasums, and says overwrites are forbidden

either way, the `1.1.0` on npm stays as the first run published it. so the wish's done-check holds whatever the second run's color.

## timeline

```
[t0] given 1.1.0 is on npm from a prior run, and trust names publish.yml
[t1] when the releaser reruns (or re-pushes tag v1.1.0)
[t2] then npm publish fails: the version already exists
[t3] then idempotify compares the local pack shasum with the registry's
[t4] then it goes green on a match, or red with both shasums on a mismatch
[t5] then npm view @ehmpathy/as-command version still reads 1.1.0, untouched
```
