# 1.vision.experience.dimensions

| axis | positions | why orthogonal to the rest |
|---|---|---|
| trust | absent · mismatched (any field off: workflow `.publish-npm.yml`, an environment set, a wrong org or repo) · `publish.yml` (all four fields as the ask states) | the npm trust record **before** the act. npm holds it apart from github and the registry's version list, so any value pairs with any act and any release state |
| act | register (admin, npmjs.com) · tag push (releaser; a re-push of the same tag counts) · rerun of the failed run (releaser) · install (consumer) | what one actor does at one boundary. the actor is a property of the act, not its own axis, so no row is empty |
| release | unpublished · published | whether this version already sits on npm. a prior run, not the act or the trust record, sets it; it is what a retry differs on |

24 cells. the act sets which other axes bite:
- `register` reads only trust: its outcome is the same whatever the release state
- `install` reads only release: npm serves a version whatever the trust record says
- `tag push` and `rerun` read all three

## repo drift — a cross-cut, walked in `case=_`

a repo change after the record is saved (a `declapract upgrade` that renames the caller, a second caller, an `environment:` on the publish job) moves the repo off the record. it is not a fourth axis: it turns a saved `publish.yml` trust into `mismatched` against the new repo, so the next tag push walks `mismatched × tag push`. what is new is when it is caught: the repo test goes red on the change, before any tag.

## the race — a cross-cut, walked in `case=_`

two runs on one tag at once (a rerun while a re-push runs) share the concurrency group `publish-refs/tags/v1.1.0` with `cancel-in-progress: true` (`publish.yml:8-10`). the later run cancels the earlier. it is not a fourth axis: each outcome collapses onto a cell already walked, by the release state the later run finds. the two outcomes carry verdicts under `## the race` in `case=_`.
