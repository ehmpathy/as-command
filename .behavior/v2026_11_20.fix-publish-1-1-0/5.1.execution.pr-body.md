## what this builds

the diagnosis of the absent `@ehmpathy/as-command@1.1.0` on npm, the steps that cure it, and a test that pins the repo half of the trust record. it changes no shipped code, because the repo is correct; the cure is an npm trust record.

- **cause**: #10 moved publish to npm oidc trusted publish. npm holds no trusted publisher for this package, so publish run `44309703170` (tag `v1.1.0`) stopped before build:
  ```
  ##[error]oidc: not configured for @ehmpathy/as-command (http 404). add oidc by-hand at https://www.npmjs.com/package/%40ehmpathy%2Fas-command/access
  ```
- **cure**: an npm maintainer of the package (npm lists `uladkasach`) opens the package's Settings → Trusted publishing → GitHub Actions, and enters Organization or user `ehmpathy`, Repository `as-command`, Workflow filename `publish.yml` (the caller, not `.publish-npm.yml`), Environment name blank. then, **within 2 days** (npm expires a new record whose first publish has not succeeded by then), a **full** rerun: `gh run rerun 44309703170 -R ehmpathy/as-command`, until 2026-12-18
  - not `--failed`: that skips the install job, and the publish job restores node_modules from a cache with no fallback install. the cache was last read 2026-11-18, so it evicts ~2026-11-25, and a `--failed` rerun past then passes oidc and fails at build
  - if the rerun goes red, the step that failed names the next move: see the outcome table under `## the ask` in `.behavior/v2026_11_20.fix-publish-1-1-0/1.vision.yield.md`
- **why it works**: `ehmpathy/helpful-errors` v1.7.6 publishes with provenance through the same `.publish-npm.yml` once its trust exists. npm validates the caller workflow's filename (docs.npmjs.com/trusted-publishers)
- **why not a token**: the last token publish was 1.0.5 on 2025-11-02. npm revoked all classic tokens on 2025-12-09, and granular write tokens expire within 90 days, so a token path also needs an admin

## 🟡 merge no v1.1.x release pr until 1.1.0 is on npm

any merge to `main` (this pr, or the open #9) opens a `v1.1.1` release pr, since `please-release` bumps patch on every commit but `chore(release):`. the harm is in that release pr's merge: v1.1.1 either 404s like v1.1.0 did, or lands and makes `npm view … version` read `1.1.1`, and a 1.1.0 rerun after it may move `latest` back to 1.1.0. so: register trust → full rerun → `npm view @ehmpathy/as-command version` reads `1.1.0` → only then merge a release pr. this pr can wait unmerged; the done-check reads npm, not `main`.
