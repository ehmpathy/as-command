# 🌙 dream: the published build should not ship compiled tests

- kind: followup (this repo, ehmpathy/as-command; the cure is the `typescript-node` practice file)
- owner: as-command maintainers
- caught 2026-11-14

## .the cue that fired

the new acceptance scan of `dist/` (peer r010, round i004) found `dist/dependencies.integration.test.js` — every `*.test.ts` compiles into `dist/`, and `files: ["/dist"]` publishes it.

## .the gap, precisely

- `tsconfig.build.json` excludes `src/**/*.test.(ts|js)`; tsc globs do not support `(a|b)` alternation, so the pattern matches no file and every test compiles
- the defect predates this pr: main's `dist/` holds `asCommand.integration.test.js`
- no adopter import reaches these files (the acceptance walk from `dist/index.js` proves it), so dpdm in adopters is unaffected; the cost is package size and test code in a prod artifact

## .the shape of the fix

- take the `typescript-node` practice's `tsconfig.build.json` (excludes `**/*.test.ts`, `**/*.test.js`, `**/.test/**/*`)
- then the `test:types` command must point at `tsconfig.json`, or tests lose their type check — the same practice owns that command
- an acceptance clamp: assert no `*.test.js` under `dist/`

## .why it is not done in this round

the file and the command it couples to belong to the `typescript-node` practice; a per-practice apply is the pave held for the radio (F03). a hand edit of one half would drop the type check on every test.
