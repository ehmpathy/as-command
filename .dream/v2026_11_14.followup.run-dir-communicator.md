# 🌙 dream: a run-dir communicator owns the run's layout, out.json, and out.write

- kind: followup (this repo, ehmpathy/as-command)
- owner: as-command maintainers
- caught 2026-11-14

## .the cue that fired

peer review r011 (round i005): the log file has an owner (`genRunLog`), but its siblings in the run dir do not. each defect below predates this pr.

## .the gap, precisely

- raw i/o in the orchestrator: `fs.mkdir` of the run dir, `fs.appendFile(outFilePath, …)`, and the `out.write` body (`mkdir` + `writeFile` on `${dir}/${name}`) sit in `asCommand`
- `out.json` is written with `appendFile`: two same-second runs with the same input share a run dir and concatenate their outputs; `writeFile` would converge
- `out.write` accepts a `name` like `../x` and writes outside the run dir
- the run id has one-second resolution, so same-input runs in one second share a dir at all (root cause of the two above)
- a failed log append masks the logic's error: when `log.json` cannot be written and the logic throws, the caller gets the `ENOENT` from the `]` seal in `finally`, never the logic's error (on main, the `catch`'s awaited `log.error` append masked it too). the console still gets the real error; the caller does not. pinned by the append-fails snapshot in `asCommand.integration.test.ts`

## .the shape of the fix

- `genRunDir({ dir, stage, name, input })` → `{ path, log: genRunLog(...), setOut({ output }), writeFile({ name, data }) }`
  - owns the path template and the file names
  - `setOut` via `writeFile` (idempotent), rendered by `asOutFileContent`
  - `writeFile` refuses a `name` that leaves the run dir (`ConstraintError`, names the fix)
- a unique run-id suffix in `asRunId` (e.g. a short random or monotonic counter), so same-second runs never share a dir
- the run dir's seal never replaces the logic's error: rethrow the logic error with the log failure as its `cause` (or an `AggregateError`), so the caller sees the real failure and the log failure both
- each a contract change (out.json bytes on a collision, a rejected `name`): snapshot moves and a minor bump

## .why it is not done in this round

pre-extant, outside the wish (drop bottleneck, keep log writes in order); a rejected `../` name and a new run-id format change behavior adopters can see (fails SAFE and CLEAN).
