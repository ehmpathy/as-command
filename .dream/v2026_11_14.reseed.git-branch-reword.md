## .the cue that fired

## .the gap, precisely

- `git.branch.rebase` only rebases onto origin/main (begin, continue, take, abort, lock)
- `git.branch.cutover` replays picked commits unchanged onto a new branch, so the result is a new pr, not a rewrite of the open one
- `git.commit.push` never force-pushes, so even a local reword could not reach the open pr
- the same holds for a plain `git.branch.rebase begin` onto origin/main: it clears a CONFLICTING pr locally, and no paved verb can push the rebased branch to it

## .the shape of the fix

- `rhx git.branch.rebase reword --sha <sha> --message @stdin [--mode plan|apply]`: replay the branch from the sha's parent with only that message changed. refuse a sha on origin/main or under a tag
- push it with `--force-with-lease` against the sha it read, and only for a branch with no merged history
- clamp: a temp repo with 3 commits; reword the middle; assert the tree hashes are the same and only that message changed
