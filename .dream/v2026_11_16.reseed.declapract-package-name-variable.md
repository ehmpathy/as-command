# 🌙 dream: declapract needs a package name apart from projectName

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy
- caught 2026-11-16

## .the cue that fired

`declapract.upgrade` on `ehmpathy/as-command` renamed the published package `@ehmpathy/as-command` → `as-command`.

## .the gap, precisely

`src/practices/node/best-practice/package.json` (check `CONTAINS`) builds both the npm name and the github urls from one variable:

```json
"name": "@declapract{variable.projectName}",
"repository": "@declapract{variable.organizationName}/@declapract{variable.projectName}",
"homepage": "https://github.com/@declapract{variable.organizationName}/@declapract{variable.projectName}",
```

a scoped package whose repo slug lacks the scope cannot satisfy both. today the rename is re-applied on every upgrade, and a restored name fails the practice check.

## .the shape of the fix

- add an optional `packageName` variable, default `projectName`, used only for `"name"`
- or derive `"name"` from the extant `package.json` when it already ends in `/<projectName>`
- fixture: `projectName: as-command`, extant name `@ehmpathy/as-command` → check passes, no rename

## .why it is not done in this round

the practice lives in another repo. here, the name was restored by hand (stone 3.1, D2), and will show as practice drift until the fix lands.
