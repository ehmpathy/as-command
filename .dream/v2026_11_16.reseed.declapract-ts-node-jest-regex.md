# 🌙 dream: ts-node-beside-esbuild-register must match jest configs only

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy
- caught 2026-11-16

## .the cue that fired

after `declapract.upgrade` on `ehmpathy/as-command`, depcheck failed on `Unused devDependencies: * ts-node`, the exact case (#660) this practice exists to fix. the practice never reported a detection.

## .the gap, precisely

`src/practices/typescript-any/bad-practices/ts-node-beside-esbuild-register/package.json.declapract.ts`, `isTsNodeStillUsed`, line 45:

```ts
.filter((name) => /^jest\..*\.ts$/.test(name))
.some((name) => !readFileSync(...).includes('@jest-config-loader'))
```

the regex matches setup files too (`jest.unit.env.ts`, `jest.integration.env.ts`, `jest.integration.env.db.ts`, `jest.integration.prepare.ts`, `jest.acceptance.env.ts`, `jest.acceptance.prepare.ts`). those are not configs, never carry the pragma, and are written by the tests practice itself. so the branch returns true in every repo with them, and `ts-node` is never removed.

## .the shape of the fix

- match configs only: `/^jest(\..+)?\.config\.ts$/` (covers `jest.config.ts`, `jest.unit.config.ts`, …)
- add an integration fixture: pragma'd configs beside pragma-less `jest.*.env.ts`, assert the bad practice is detected and `ts-node` removed
- why the bug shipped: the extant fixture `src/.test/assets/tool-swap-removals/repo-after-swaps/` holds jest configs but no `jest.*.env.ts`, unlike any repo the tests practice produces (`gh search code ... --filename jest.unit.env.ts` finds none there)

## .why it is not done in this round

the practice lives in another repo. here, `ts-node` was removed by hand (stone 3.1, D3).
