# 🌙 dream: set.package owes a remove verb and a --help

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (mechanic role, `skills/set.package/`)
- caught 2026-11-16

## .the cue that fired

a declapract upgrade repair had to drop two deps (`bottleneck`, `ts-node`). raw `pnpm install` is not granted on a crew tree, and the only paved package skills are `set.package.install` and `set.package.upgrade`.

## .the gap, precisely

- no skill removes a dependency. `set.package.install` refuses an installed package; `set.package.upgrade` refuses an absent one
- the lockfile refresh after a hand edit of `package.json` was reached only through a side channel: `rhx set.package.upgrade --package with-bottleneck --to 0.1.2` (same version, so the `pnpm add` reconciles the lockfile)
- `rhx set.package.install --help` exits 2 with `error: unknown argument: --help` (`rule.require.help-on-demand`)

## .the shape of the fix

- add `set.package.remove --package <name> --reason '<why>'`: runs `pnpm remove` (or `npm uninstall` when `package-lock.json` exists), persists the reason under `.route/v{date}.package.remove/`, and fails fast if the package is absent
- or add `set.package.sync` that runs a plain lockfile reconcile, for the case where `package.json` was edited by a practice tool
- add `--help` / `-h` to `set.package.install` and `set.package.upgrade`

## .why it is not done in this round

the skill lives in another repo (rhachet-roles-ehmpathy); this route repairs `as-command`.
