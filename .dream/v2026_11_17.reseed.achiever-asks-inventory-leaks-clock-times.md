# 🌙 dream: the achiever's asks inventory must not carry clock times into a tracked file

- kind: reseed
- owner: ehmpathy/rhachet-roles-bhrain (achiever role: the ask-capture hook, `goal.guard`)
- caught 2026-11-17

## .the cue that fired

on `ehmpathy/as-command`, `rhx git.commit.set --mode apply` failed in `.husky/check.timestamps.sh`: a peer message that named clock times (`[clock] CT`, twice) was copied verbatim into the route's `.goals/asks.inventory.jsonl`, which is staged with the route.

## .the gap, precisely

three paved guards collide, and none offers a lever to the driver:

- `check.timestamps.sh` forbids any clock time in a tracked file and allows no exemption ("remove or mask it")
- `goal.guard` forbids any command that names `.goals/`, so the driver cannot unstage, mask, or inspect the file
- the ask-capture hook writes each peer message verbatim, with `"hash"` = sha of the content, so a hand mask would also break coverage

result: any peer message with a clock time blocks every commit of the route until a human intervenes.

## .the shape of the fix

- mask clock times at capture (`HH:MM` → `[clock]`) before the hash and the write, the same mask the timestamp hook asks for; or
- keep raw `asks.inventory.jsonl` out of git (route `.gitignore`), and track only the distilled goals; and
- give `goal.guard` a paved skill for this case (e.g. `goal.memory.mask --clock`), so a driver is never left with only a guard-evasion path

## .why it is not done in this round

the skill lives in another repo, and every in-repo option either breaks a guard or alters a peer's words. a human decision unblocks this commit.
