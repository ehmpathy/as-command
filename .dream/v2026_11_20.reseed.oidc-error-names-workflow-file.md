# 🌙 dream: the oidc-auth error names the workflow file to register

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy (the `.publish-npm.yml` practice)
- caught 2026-11-20

## .the cue that fired

as-command's v1.1.0 publish failed with `oidc: not configured ... (http 404)`. the vision's sharpest path is an admin who registers `.publish-npm.yml`, because that file holds `npm publish`. npm validates the caller workflow instead (docs.npmjs.com/trusted-publishers).

## .the gap, precisely

the `verify oidc auth` error names the access url but not the values to enter. the one non-obvious value is the workflow filename, so the error does not teach the fix.

it also prints "not configured" for every non-2xx code. a 401 or an empty token (an absent `id-token` grant), a 429, or a 5xx read as an absent record, and send the admin to a page that holds no fault. and a 404 on a record older than 2 days means npm expired it, which the error does not say.

## .the shape of the fix

in the practice's `.publish-npm.yml`, derive the caller file from `$GITHUB_WORKFLOW_REF` (`owner/repo/.github/workflows/<file>@ref`) and add it to the `::error::` line, e.g. `register trusted publisher: org=ehmpathy repo=as-command workflow=publish.yml`.

use `github.workflow_ref`, never `job.workflow_ref`: per the github contexts reference, `job.workflow_ref` "refers to the reusable workflow file" and equals `github.workflow_ref` only "for jobs defined directly in a workflow file". so inside the reusable `.publish-npm.yml`, `github.workflow_ref` is the caller — the file npm validates.

branch the message on the code: 404 → "no trusted publisher, or one that expired unvalidated after 2 days" plus the four values; 401 or an empty token → "the oidc token was not issued; check `permissions: id-token: write` on the caller"; 429 / 5xx → "the registry failed; rerun".

and the practice's readme owes the one by-hand step every adopter takes: register the four fields, then within 2 days do a full rerun of the failed publish (not `--failed`, which skips the cache-miss install), inside github's 30-day rerun window.

## .why it is not done in this round

the file is owned by the practice. a local edit drifts on the next `declapract upgrade`, and the fix helps every package that adopts the practice.
