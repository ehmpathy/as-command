# 🌙 dream: publish.yml accepts a workflow_dispatch from a v* tag (hypothesis)

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy (the `publish.yml` practice)
- caught 2026-11-20

## .the cue that fired

as-command's 1.1.0 cure is a rerun of one failed run, which github allows for 30 days. past that, the path is a tag delete and re-push: not atomic, and it can demote the tag's github release to a draft.

## .the gap, precisely

`publish.yml` fires only on `push: tags: v*`. a version whose publish failed has no way to retry past the rerun window without a tag rewrite.

## .the shape of the fix

add `workflow_dispatch` to `publish.yml`, plus a first step that refuses any `github.ref` not of the form `refs/tags/v*` (else a dispatch from a branch would publish that branch's `package.json` version). then `gh workflow run publish.yml --ref v1.1.0` retries a tag at any age.

hypothesis, unverified: docs.npmjs.com/trusted-publishers lists four record fields (org, repo, workflow filename, environment) and names `workflow_dispatch` as a publish path, but is silent on ref and event. a first dispatch from a tag must show the oidc exchange succeeds before this ships.

## .why it is not done in this round

the file belongs to the practice, and the hypothesis wants one live probe first.
