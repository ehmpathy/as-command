# 🌙 dream: the practice tests its own publish step scripts

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy (the `.publish-npm.yml` practice)
- caught 2026-11-20

## .the cue that fired

as-command's verification wanted proof that `verify oidc auth` and `idempotify` branch right on each response. a test of those `run:` blocks in as-command would give practice-owned files a second owner, and go red in a downstream repo on every legit upgrade of the step text.

## .the gap, precisely

no test in the practice runs the `run:` blocks of `.publish-npm.yml`. their branches (oidc 2xx / 404 / 401 / 5xx / curl failure; idempotify shasum match / mismatch / absent version) are proven only by the runs that happen to hit them in some adopter's ci.

## .the shape of the fix

in the practice repo, a test that extracts each named step's `run:` block from the template, runs it under `bash -e` with a PATH that holds only stub `curl` / `npm` / `jq` / `pnpm`, and snapshots stdout and exit code per case. data-driven case rows; a pure transformer for the block extract. the test and the template change in one pr.

## .why it is not done in this round

the file and its test belong in the practice repo. as-command pins only the four trust fields its npm record depends on.
