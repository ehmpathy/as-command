# 🌙 dream: please-release opens no release pr when no shipped file changed

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy (the `please-release` action)
- caught 2026-11-20

## .the cue that fired

as-command's fix pr carries only `.behavior/` and `.dream/` files. a peer review traced that its merge to `main` still opens a `v1.1.1` release pr, which, if released before 1.1.0 lands, makes `npm view … version` read 1.1.1 and may point `latest` back at 1.1.0 when the 1.1.0 rerun publishes after it.

## .the gap, precisely

- `.github/actions/please-release/action.yml:180` defaults the bump to `patch` for any commit type except `chore(release):`
- `package.json` declares `files: ["/dist"]`, so a docs-only commit yields a byte-identical tarball under a new version
- `.publish-npm.yml` runs `npm publish … --provenance` with no `--tag`, so an older version published last takes `latest`

## .the shape of the fix

in `please-release`, diff the commits since the last tag against the paths in `package.json#files` (plus `package.json` itself); when none changed, open no release pr. separately, publish with `--tag latest` only when the version is the highest on npm.

## .why it is not done in this round

the action is owned by the practice; a local edit drifts on the next `declapract upgrade`. this route holds the pr unmerged until 1.1.0 lands instead.
