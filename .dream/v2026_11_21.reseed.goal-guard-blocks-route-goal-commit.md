# 🌙 dream: route goals can be committed through a paved path

- kind: reseed (ehmpathy/rhachet-roles-bhrain, role=achiever, `goal.guard`; or role=mechanic `git.stage.add`)
- owner: rhachet-roles-bhrain maintainers
- caught 2026-11-21

## .the cue that fired

as-command pr #9, done gate: commit every path the pr lacks. `goal.memory.set` wrote four goals into the route (`.behavior/<route>/.goals/*.goal.yaml`, `*.status=*.flag`, `asks.coverage.jsonl`). `rhx git.stage.add <those paths>` was refused by `goal.guard`: `direct access to .goals/ is forbidden`.

## .the gap, precisely

- `goal.guard` matches the text `.goals/` in any Bash command, so a stage of a goal file is refused the same as a read or a write of it
- the goal skills persist goals into the route, which is committed, yet no paved verb can stage them
- the two exits left are both wrong: a glob that dodges the literal text (a workaround of the guard), or `git.commit.set --unstaged include` (sweeps in the asks log and box-local scratch)
- so route goals stay uncommitted on every route, and the record of what was promised never reaches the pr

## .the shape of the fix

- `rhx goal.memory.stage [--include coverage]`: stage the route's goal yaml, status flags, and coverage map; never the asks inventory
- or: `goal.guard` permits `rhx git.stage.add` of `*.goal.yaml`, `*.status=*.flag`, and `asks.coverage.jsonl` under `.goals/`, and still refuses `asks.inventory.jsonl`
- clamp: a temp route with one goal; the stage succeeds and `git diff --cached --name-only` lists the yaml and flag; a stage of `asks.inventory.jsonl` is refused

## .why it is not done in this round

the guard belongs to rhachet-roles-bhrain. the four goals of this route stay uncommitted until a paved stage path exists.
