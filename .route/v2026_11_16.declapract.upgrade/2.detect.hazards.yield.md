## hazards

### H1 · test · lint fails on a dpdm cycle in `bottleneck`

- **what changed**: new `test:lint:cycles` (dpdm with `--transform`) walks `src/**` into node_modules
- **why it breaks**: `bottleneck@2.19.5` has an internal cycle (`lib/Bottleneck.js -> lib/Group.js`), so `npm run test:lint` exits 1. it also halts the chain before `test:lint:deps` runs
- **constraint**: `rule.forbid.dpdm-exclude-change` forbids adding a prod dep to the `.dpdmrc.yaml` exclude list. the cycle is inside a third-party prod dep, not in our code
- **verify**: `rhx git.repo.test --what lint`

### H2 · config · package renamed and marked private (urgent: blocks publish AND flips repo private)

- **what changed**: `package.json` `name` `@ehmpathy/as-command` → `as-command`, plus `"private": true`
- **why it breaks**:
  - `npm publish` refuses a private package, and the published name (`@ehmpathy/as-command`, per readme lines 11 and 21) would drift. consumers would get no new release
  - 🔴 `provision/github.repo/resources.ts:48` derives `visibility` from `pkg.private` (`pkg.private === false ? 'public' : 'private'`). on merge to main, `provision.yml` would apply and flip the public repo `ehmpathy/as-command` to **private**
- **fix shape**: restore `"name": "@ehmpathy/as-command"`, and set `"private": false` (explicit, since the provision code fails closed on absent)
- **verify**: `cat package.json | jq '.name, .private'` should give `"@ehmpathy/as-command"` and `false`

### H3 · cicd · publish auth moved from `NPM_TOKEN` to npm oidc trusted publish

- **what changed**: `.publish-npm.yml` drops the `npm-auth-token` secret and adds a `verify oidc auth` step plus `--provenance`
- **why it breaks**: a human must first enable trusted publish for `@ehmpathy/as-command` at npmjs.com. without it, the `verify oidc auth` step fails with `exit 1`
- **verify**: the publish job on the first release after merge; a human confirms the npm package access settings

### H4 · cicd · test workflow now needs keyrack firewall + optional aws oidc

- **what changed**: `.test.yml` adds `keyrack firewall --env test` (uses `secrets: inherit`), an aws oidc role step gated on `vars.CREDS_CICD_AWS_PREP_OIDC_ROLE_ARN`, and `start:testdb --if-present`
- **why it may break**: the firewall hydrates extended manifests from the `.agent/repo=*` symlinks that `prepare:rhachet` creates. if CI skips that, or the keys declared under `env.test` are absent from repo secrets, the job fails
- **verify**: CI run on push (stone 3.3)

### H5 · test · integration global setup reaches out to livedb + keyrack

- **what changed**: `jest.integration.prepare.ts` calls `useWakeOfLivedb({ env: 'prep' })` and `useKeyrack({ env: 'test' })`. `jest.integration.env.ts` calls `useTestdbPortOverride` + `useWakeOfTestdb`
- **why it may break**: this package has no db. the wake is self-gated, a no-op without a declared db tunnel, so it passed locally. CI is not yet proven
- **verify**: local passed (9/9). CI run confirms

### H6 · config · new prod deps that ship to consumers but only dev code uses

- **what changed**: `dependencies` gains `domain-objects`, `helpful-errors`, `type-fns`, `with-bottleneck`
- **why it may break**:
  - `helpful-errors` and `domain-objects` are imported only by jest env files and `provision/`, never by `src/`
  - `with-bottleneck` has no import anywhere, so depcheck (blocked behind H1) will likely flag it unused
  - every consumer would install four extra packages
- **verify**: depcheck once H1 clears. `rhx grepsafe --pattern "from '(domain-objects|helpful-errors|with-bottleneck)" --path src` should find no match

### ~~H7 · config · node 20 → 22, target es6 → es2020, module node16~~ — struck: `types` + `build` pass, entry fields unchanged

- **what changed**: `.nvmrc` `v22.21.0`; tsconfig `target es2020`, `module/moduleResolution node16`, `extends` → `@tsconfig/strictest` + `@tsconfig/node20`
- **why it may break**: output syntax rises to es2020, so consumers on node < 14 break (acceptable). types pass, build passes

### ~~H8 · test · ts-jest → @swc/jest; jest 29 → 30~~ — struck: integration 9/9 pass under jest 30 + swc

- **what changed**: transform is `@swc/jest`; configs load via `esbuild-register`
- **why it may break**: swc skips type checks in tests, but `test:types` covers that
- **verify**: integration passed under jest 30 + swc. no action

### H10 · cicd · release-please → custom `please-release` action via the rhelease github app

- **what changed**: `release.yml` drops `RELEASE_PLEASE_GITHUB_TOKEN` and mints a token from `vars.RHELEASE_APP_ID` + `secrets.RHELEASE_APP_PRIVATE_KEY`
- **why it may break**: if the rhelease app is not installed on this repo, or the var/secret is absent, the release job fails on every push to main
- **verify**: `gh variable list` / `gh secret list` show `RHELEASE_APP_ID` / `RHELEASE_APP_PRIVATE_KEY` (org or repo level); first push to main

### H11 · cicd · new `provision.yml` runs declastruct against github repo settings

- **what changed**: new workflow on every `pull_request` (plan) and on main/tags (apply), via the `DECLASTRUCT_GITHUB_CONFORMER_APP_ID` var + private key secret
- **why it may break**:
  - absent app creds → the provision job fails on the PR
  - on main, apply rewrites repo settings: squash-only merges, branch protection that requires 10 named status checks, 4 github environments, a release-tag ruleset. a human should expect these settings to change
  - couples to H2 (visibility)
- **disproven sub-risk**: all 10 required check contexts map to real job ids (`.install.yml` `pnpm`; `.test.yml` `enshard`, `test-commits` … `test-acceptance-locally`; `review.yml` `pullreq-title`), so protection will not lock merges on a phantom check
- **verify**: the provision plan output on the PR; app creds present

### ~~H12 · test · commitlint type-enum narrowed~~ — struck: `HEAD` is the `v1.0.5` tag commit, so `test:commits` has zero extant commits to fail. the narrowed set binds only new commits, which follow `type(scope):` with allowed types

- **what changed**: `commitlint.config.js` allows only `break|feat|fix|chore|revert|cont`, and forbids `!`
- **why it may break**: `test:commits` lints commits since the last tag. commits since `v1.0.5` are all `fix(...)`/`chore(...)`, so the current history passes. new `docs:`/`refactor:`/`test:` commits would fail
- **verify**: `rhx git.repo.test --what commits` once on the branch (or CI `test-commits`)

### ~~H13 · config · `changelog.md`, `.eslintrc.js`, `prettier.config.js`, `.prettierignore` deleted~~ — struck as a breakage; kept as a flag for the human

- **what changed**: lint and format move to biome. the release changelog now lives in release PR bodies (`please-release` writes `/tmp/changelog.md` into the PR)
- **why it may break**: no command or workflow reads these files any more. the cost is the in-repo release history in `changelog.md` (v1.0.0–v1.0.5), which git and github releases still hold
- **verify**: no action; flag to the human as an intended loss
