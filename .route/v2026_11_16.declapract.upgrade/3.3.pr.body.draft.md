## repairs on top of the upgrade

- **`bottleneck` → `with-bottleneck`** (`src/asCommand.ts`): the new dpdm check found a require cycle inside `bottleneck@2.19.5`, a prod dep that ships to consumers. it is abandoned upstream and policy forbids an exclude, so it is replaced, as the upgrade's own bottleneck practice intends
  - 🟡 behavior: the old `new Bottleneck({ maxConcurrency: 1 })` used an option bottleneck ignores (`maxConcurrent`), so log appends were never serialized. `genBottleneck({ concurrency: 1 })` serializes them, as the code intended
- **package identity**: the template renamed the package to `as-command` and set `"private": true`. that would block `npm publish`, and the provision workflow maps `private` to repo visibility, so it would flip this public repo private on merge. restored `@ehmpathy/as-command` with an explicit `"private": false`
- **`ts-node` removed**: jest configs now load via `esbuild-register`, so `ts-node` had no user and depcheck failed on it
